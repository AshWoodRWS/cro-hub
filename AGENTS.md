## What Lovable manages

Rules outside this block are the project's own. Change the pieces below in
Lovable, not by hand. With the [Lovable MCP](https://mcp.lovable.dev)
connected, `send_message` asks Lovable to do it; otherwise ask the user to
use the editor.

- **Database.** Do not add or edit `supabase/migrations/` or `drizzle/`.
  Ask Lovable to change the schema.
- **Generated files.** Do not edit a file whose header says it is automatically
  generated.
- **AI gateway.** Keep model calls on Lovable's gateway, and keep
  `LOVABLE_API_KEY` out of browser code.
- **Connectors.** Lovable provides native connectors. `list_connectors` shows
  which are enabled; `add_connector` only returns the dashboard link. When a
  connector is enabled, calls go through the connector gateway and need
  `LOVABLE_API_KEY`. When Lovable does not provide one, users can bring their
  own key and store it in Secrets.
- **Secrets.** Lovable manages them. Do not put secret values in the repo.

## CRO application rules
- Use leaf routes for the five reporting views and root-validated search filters so drill-downs preserve site and date context.
- Keep labelled synthetic reporting data separate from private Cloud tables; missing live sources must never appear connected.
- CSV parsing and reporting calculations live in browser-safe domain modules with concrete tests, so source definitions remain consistent.
- Private reporting tables require approved roles, with admin-only writes; never auto-approve the current identity.
- AI recommendations use an identity-verified same-origin streaming route, reconstruct selected sample evidence on the server, and validate evidence citations before accepting output; this cannot grant private-report access.
- AI Gateway Responses calls use request-local correlation helpers and strict structured output; persist terminal access blocks and never automatically replay denied or refused requests.
